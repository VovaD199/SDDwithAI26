# Специфікація: контактна форма (приклад, 8 артефактів з ID)

> ЗАПАСНИЙ ПРИКЛАД для дня 4. Спирається на аналіз дня 2 (`../day-2/contact-form-feature.md`) і код шаблону. Рівні впевненості: **Grounded** (є в коді чи запиті), **Inferred** (логічний висновок), **Invented** (вигадка: тут не використовується, невідоме винесено у відкриті питання). Читайте й адаптуйте до власної версії (див. `materials/fallback/README.md`). Структура відповідає `materials/day-4/templates/ba-refinement-template.md`.

| Поле | Значення |
|---|---|
| ID фічі | FEAT-CONTACT-001 |
| Назва | Контактна форма: обов'язковий телефон і вкладення |
| Статус | Уточнення |
| Джерело | issue «Contact form — update validation and notifications» |

## 1. Проблема

**Кого стосується:** відвідувачів сайту, що пишуть фонду, і працівників, які опрацьовують звернення. **Біль:** телефон необов'язковий, документи (CV, портфоліо) надіслати не можна. **Чому зараз:** запит від команди фонду (issue). **Бажаний результат:** фонд отримує звернення з телефоном і, за бажанням, документом.

## 2. Межі

| ID | У межах | Примітка |
|---|---|---|
| IN-01 | Обов'язковий телефон у формі контактів | Grounded (issue) |
| IN-02 | Необов'язкове вкладення PDF до 5 МБ | Grounded (запит у навчальному кейсі) |
| IN-03 | Відображення телефону й вкладення у сповіщенні | Grounded (issue) |

| ID | Виключення | Причина |
|---|---|---|
| OUT-01 | Інші типи файлів | У запиті лише PDF |
| OUT-02 | Антиспам і обмеження частоти запитів | Окрема тема, не в запиті |
| OUT-03 | Зміна інших форм (`GetNotesModal`) | Не в запиті, питання Q-03 |

## 3. Актори й потік

Актори: відвідувач, працівник фонду. Основний потік: відвідувач заповнює форму → форма перевіряє поля → запит на `/api/collaboration` → сервер перевіряє → «успіх» → вікно підтвердження → працівник отримує сповіщення (зараз сповіщення не формується).

## 4. Бізнес-правила

| ID | Коли | Тоді | Інакше | Джерело |
|---|---|---|---|---|
| RULE-01 | Телефон порожній | Форма й API відхиляють запит | Приймають | Зміна з issue |
| RULE-02 | Телефон не `+` і цифри або не 11–16 символів | Помилка формату | Приймається | Код (`validateContactData.ts`) |
| RULE-03 | Вкладення не PDF або понад 5 МБ | Помилка, файл не додається | Додається | Запит |
| RULE-04 | Повідомлення не в межах 10–1000 | Помилка | Приймається | Код (константа; число окремо у формі) |
| RULE-05 | Згода з політикою не поставлена | Форма не відправляється | Відправляється | Код (лише UI) |
| RULE-06 | Email за правилом клієнта й сервера | Різні правила | N/A | Код (розбіжність) |
