## Крок 0. Підготовка до курсу (до заняття)

Встановіть Git і Node.js (кроки 1–2) і надішліть ментору скріншот результату команд:

```bash
git --version
node -v
```

Очікується: Git 2.x і Node `v22` або новіше.

## Крок 1. Встановлення Git

**Windows** (PowerShell):

```powershell
winget install --id Git.Git -e
```

Якщо `winget` недоступний, завантажте інсталятор з https://git-scm.com/download/win і залиште налаштування за замовчуванням.

**macOS** (Terminal):

```bash
xcode-select --install
```

Або `brew install git`, якщо у вас є Homebrew.

**Linux** (Debian/Ubuntu):

```bash
sudo apt update && sudo apt install -y git
```

(Fedora: `sudo dnf install -y git`.)

**ПЕРЕВІРТЕ:** закрийте й відкрийте термінал заново, виконайте `git --version`.

Один раз налаштуйте ім'я та пошту (для комітів):

```bash
git config --global user.name "Ваше Імʼя"
git config --global user.email "you@example.com"
```

## Крок 2. Встановлення Node.js 22+

Завантажте інсталятор для вашої ОС з https://nodejs.org/en/download (версія 22 або новіша) і встановіть із параметрами за замовчуванням. Npm встановиться разом із Node.

**Linux** (приклад через nvm):

```bash
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash
# перезапустіть термінал
nvm install 22
```

**ПЕРЕВІРТЕ:**

```bash
node -v
npm -v
```

**ЯКЩО НЕ ВИЙШЛО:** немає прав адміністратора на корпоративному ноутбуці. Напишіть ментору до заняття; окремий PDF «Встановлення без прав адміністратора» (буде додано).

> Для викладача: перевірити команди `winget` та версію nvm на чистих Windows і macOS під час прогону. Окремі PDF встановлення: Windows, macOS, Linux.

## Крок 5. Встановлення Cursor і відкриття проєкту

1. Завантажте Cursor з https://cursor.com і встановіть. Увійдіть в обліковий запис (за потреби корпоративний).
2. Відкрийте папку проєкту: **File → Open Folder** і виберіть `SDDwithAI26-<ваше-імʼя>`.
3. На запит «Trust this workspace?» виберіть **Yes, I trust the authors**.

Необов'язково, з терміналу: `cursor .`

### Як відкрити термінал у Cursor

Термінал у Cursor зазвичай розташований унизу вікна, але на початку він може бути прихований. Відкрийте його одним із трьох способів.

**Спосіб 1. Клавіатурою (найшвидший)**
- Windows / Linux: `Ctrl + Shift + ~` (клавіша зі знаком `` ` `` зліва від цифри 1; на українській розкладці це та сама фізична клавіша)
- macOS: `Control + ~` (те саме: клавіша зі знаком `` ` ``)

**Спосіб 2. Через меню**
1. У верхньому меню виберіть **Terminal**.
2. Натисніть **Terminal → New Terminal**.
3. Унизу відкриється панель терміналу.

**Спосіб 3. Через палітру команд**, якщо меню **Terminal** не видно
1. Натисніть `Ctrl + Shift + P` (Windows/Linux) або `Cmd + Shift + P` (macOS).
2. Введіть `Terminal: Create New Terminal`.
3. Натисніть `Enter`.

**ПЕРЕВІРТЕ:** унизу вікна Cursor з'явився термінал із запрошенням для введення команд, і шлях у ньому веде до папки вашого проєкту `SDDwithAI26-<ваше-імʼя>`. Якщо шлях інший, закрийте термінал і відкрийте його знову, коли папка проєкту вже відкрита.

**ПЕРЕВІРТЕ:** ліворуч видно дерево файлів; чат агента відкривається за `Ctrl+B` (Windows/Linux) або `Cmd+B` (macOS).

## Крок 6. Запуск застосунку

У вбудованому терміналі Cursor (**Terminal → New Terminal**) виконуйте команди по черзі.

**1. Створіть файл налаштувань:**

```bash
cp .env.example .env         # Windows PowerShell: Copy-Item .env.example .env
```

Після цього у списку файлів Cursor має з'явитися файл `.env`. У ньому лише одна необов'язкова змінна, значення за замовчуванням достатньо. Файл `.env` у Git не потрапляє (він у `.gitignore`).

**2. Встановіть залежності:**

```bash
npm install
```

Ця команда читає `package.json` і завантажує всі бібліотеки, потрібні проєкту. Це схоже на встановлення компонентів, без яких програма не працюватиме. Час: зазвичай від кількох секунд до кількох хвилин (перший раз довше). У проєкті з'явиться папка `node_modules/`.

**3. Запустіть застосунок:**

```bash
npm run dev
```

Ця команда запускає локальний сервер розробки. Коли термінал покаже, що застосунок готовий, відкрийте http://localhost:3000/en у браузері.

**ПЕРЕВІРТЕ:** відкривається сайт Фонду Лятошинського. Перейдіть на сторінки «Про фонд» і «Контакти»; зверніть увагу, які розділи справжні, а які мають заглушку.

Зупинити застосунок: `Ctrl+C` в терміналі.

### Що відбувається під час `npm install`

Структура вашого проєкту (скорочено):

| Файл або папка | Призначення |
|---|---|
| `package.json` | Список залежностей і команд проєкту (`npm run dev`, `npm test`) |
| `package-lock.json` | Зафіксовані точні версії бібліотек, щоб у всіх було однаково |
| `.env` | Налаштування (локальний файл, у Git не потрапляє) |
| `app/` | Код застосунку: сторінки, API, сервіси |
| `i18n/messages/` | Тексти інтерфейсу українською й англійською |
| `scripts/` | Скрипти, зокрема демо-дані (seed) |
| `node_modules/` | З'являється після `npm install`: завантажені бібліотеки |

### Якщо ви знайомі з Python: порівняння з Node.js

| Python | Node.js | Призначення |
|---|---|---|
| `python -m venv .venv` | не потрібно | Підготовка середовища |
| `.venv\Scripts\activate` (Windows) або `source .venv/bin/activate` (macOS/Linux) | не потрібно | Активація середовища |
| `pip install -r requirements.txt` | `npm install` | Встановлення залежностей |
| `requirements.txt` | `package.json` | Опис залежностей |
| `.venv/` | `node_modules/` | Локальне зберігання бібліотек |
| `python main.py` | `npm run dev` | Запуск застосунку |

Важливий нюанс: `venv` створює ізольоване середовище Python разом із його пакетами, тоді як `node_modules` зберігає лише бібліотеки проєкту. Версією самого Node.js зазвичай керують окремо, наприклад через `nvm`.

**ЯКЩО НЕ ВИЙШЛО:**
- Порт 3000 зайнятий: Next.js запропонує інший, використайте адресу з терміналу.
- `npm install` падає: перевірте `node -v` (потрібно 22+), повторіть із мережею без VPN.
- Сторінка порожня після змін: зупиніть сервер (`Ctrl+C`) і запустіть знову.

База даних тут у пам'яті й наповнюється демо-даними при кожному запуску, тож остаточно нічого зламати неможливо.

## Крок 8. Основи Markdown (5 хвилин)

Достатньо чотирьох конструкцій:

```markdown
# Заголовок
## Підзаголовок
- пункт списку
| Колонка A | Колонка B |
|---|---|
| значення | значення |
```

Усе інше в інструкціях для AI це звичайний текст. Чіткість важливіша за обсяг.

Документація з Markdown: [Основи синтаксису (Markdown Guide)](https://www.markdownguide.org/basic-syntax/) і [Базове форматування на GitHub](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax).

## Крок 9. Постійні інструкції для агента: `AGENTS.md`

`AGENTS.md` лежить у корені проєкту, Cursor читає його автоматично. Аналітик не пише код, але пише інструкції.

**У ЧАТ CURSOR:**

```text
На основі того, що ти знаєш про цей проєкт, напиши стартовий файл AGENTS.md
для нового члена команди, який є бізнес-аналітиком.

Включи:
- однопараграфовий опис проєкту
- основні сторінки та їх бізнес-призначення (таблицею)
- конвенції: TypeScript, без default export, українська (uk) як основна мова
- примітку, що це навчальний репозиторій і БД скидається при кожному запуску
```

Перегляньте результат, **виправте неточності** (це ваша аналітична частина) і збережіть як `AGENTS.md` у корені.

**ПЕРЕВІРТЕ:** закрийте чат, відкрийте новий і запитайте:

```text
Що це за проєкт? Відповідай так, ніби я щойно долучився до команди.
```

Агент має відповісти термінами з вашого `AGENTS.md`. Якщо ні, перезапустіть Cursor.

**Необов'язково (правило для агента).** Правила, прив'язані до типів файлів, лежать у `.cursor/rules/`. Якщо хочете, попросіть агента створити одне правило, наприклад для документів у `docs/`:

```text
Створи правило Cursor у .cursor/rules/ для файлів docs/**/*.md:
одна тема на файл, на початку заголовок і коротке пояснення, навіщо документ потрібен.
Без паролів, токенів і особистих даних.
```

Агент може створити файл правила англійською: це нормально. Потім **прочитайте створений файл і відредагуйте його**, якщо там є зайве або щось не збігається з тим, що ви хотіли. Якщо правило створено, додайте його до коміту на кроці 11.

## Крок 10. Діаграма архітектури (Mermaid)

**У ЧАТ CURSOR:**

```text
Вивчи структуру проєкту, зокрема app/[lang]/, app/api/, app/services/,
app/infrastructure/ та app/di/.

Згенеруй Mermaid-діаграму flowchart TD, що показує:
- основні сторінки
- API-маршрути, які вони викликають
- сервіси, які використовують ці маршрути
- інфраструктуру (моделі/репозиторії БД), від якої залежать сервіси

Підписуй вузли справжніми назвами папок або файлів.

Створи файл docs/architecture.md (папку docs створи, якщо її немає) і запиши в нього:
- короткий вступ (2–3 речення) про те, що показує діаграма;
- діаграму в блоці коду з міткою mermaid.
```

**ПЕРЕВІРТЕ:** у папці `docs/` з'явився файл `architecture.md`. Якщо файлу немає (агент лише показав діаграму в чаті), напишіть: «Збережи діаграму у файл docs/architecture.md». Переглянути діаграму можна в попередньому перегляді Markdown у Cursor (`Ctrl+Shift+V` / `Cmd+Shift+V`) або на https://mermaid.live.

**Обговорення:** що на діаграмі відсутнє? Де в цій схемі працюють ваші знання про бізнес?

## Крок 11. Здача: Pull Request

1. Створіть гілку й перегляньте, що змінилось:

```bash
git checkout -b day-1
git status
```

`git status` має показати нові файли `AGENTS.md` і `docs/architecture.md`. Якщо одного з них немає, поверніться до кроку 9 або 10.

2. Додайте файли двома окремими командами й закомітьте:

```bash
git add AGENTS.md
git add docs/architecture.md
git status
git commit -m "docs: add AGENTS.md and architecture diagram (day 1)"
git push -u origin day-1
```

**Правило в `.cursor/rules` (необов'язково).** Якщо під час кроку 9 агент створив файл правила (наприклад, `.cursor/rules/<назва>.mdc`), прочитайте його, відредагуйте (чи збігається зміст із тим, що ви хотіли?) і додайте так само окремою командою:

```bash
git add .cursor/rules/<назва-файлу>.mdc
```

Якщо правила немає, пропустіть цей крок: воно не обов'язкове.

3. На GitHub відкрийте запропонований **Compare & pull request** → **Create pull request** (у вашому репозиторії, з гілки `day-1` у `main`).
4. Надішліть ментору **посилання на PR** (канал: `<буде вказано в Moodle>`).

**ПЕРЕВІРТЕ перед комітом:** `git status` не показує `.env`, `node_modules` чи інші службові файли.

**Обов'язкове:** `AGENTS.md` + `docs/architecture.md`. **Додатково:** одне правило в `.cursor/rules`.

## Критерії перевірки (ментору)

1. Виконано всі кроки: `AGENTS.md` і діаграма в PR.
2. `AGENTS.md` відповідає реальному проєкту (немає вигаданих сторінок).
3. Видно власну правку (не лише AI-текст).
4. Немає службових файлів і секретів.
