# День 1. Старт і контекст проєкту: покрокова інструкція

> ЧЕРНЕТКА v1. Для учасників (Moodle). Позначки `<…>` треба замінити. Адреса шаблонного репозиторію буде додана, коли він буде готовий. Примітки для викладача позначені «Для викладача».

## Мета дня

До кінця дня у вас є:
- встановлені Git, Node.js 22+ та Cursor;
- власна копія шаблонного репозиторію lf-client на GitHub і локально;
- запущений застосунок у браузері;
- файл `AGENTS.md` і діаграма Mermaid, здані як Pull Request.

## Як користуватися інструкцією

| Позначка | Значення |
|---|---|
| **КОПІЮЙТЕ** | Команди й тексти, які треба скопіювати точно |
| **У ЧАТ CURSOR** | Промпт для чату агента Cursor |
| **ПЕРЕВІРТЕ** | Контрольна точка: порівняйте з описом |
| **ЯКЩО НЕ ВИЙШЛО** | Запасний шлях |

Якщо ви пропустили заняття, пройдіть кроки по черзі й дивіться запис.

## Крок 0. Підготовка до курсу (до заняття)

Встановіть Git і Node.js (кроки 1–2) і надішліть ментору скріншот результату команд:

```bash
git --version
node -v
```

Очікується: Git 2.x і Node `v22` або новіше.

## Крок 1. Встановлення Git

**Windows** (PowerShell):

```powershell
winget install --id Git.Git -e
```

Якщо `winget` недоступний, завантажте інсталятор з https://git-scm.com/download/win і залиште налаштування за замовчуванням.

**macOS** (Terminal):

```bash
xcode-select --install
```

Або `brew install git`, якщо у вас є Homebrew.

**Linux** (Debian/Ubuntu):

```bash
sudo apt update && sudo apt install -y git
```

(Fedora: `sudo dnf install -y git`.)

**ПЕРЕВІРТЕ:** закрийте й відкрийте термінал заново, виконайте `git --version`.

Один раз налаштуйте ім'я та пошту (для комітів):

```bash
git config --global user.name "Ваше Імʼя"
git config --global user.email "you@example.com"
```

## Крок 2. Встановлення Node.js 22+

Завантажте інсталятор для вашої ОС з https://nodejs.org/en/download (версія 22 або новіша) і встановіть із параметрами за замовчуванням. Npm встановиться разом із Node.

**Linux** (приклад через nvm):

```bash
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash
# перезапустіть термінал
nvm install 22
```

**ПЕРЕВІРТЕ:**

```bash
node -v
npm -v
```

**ЯКЩО НЕ ВИЙШЛО:** немає прав адміністратора на корпоративному ноутбуці. Напишіть ментору до заняття; окремий PDF «Встановлення без прав адміністратора» (буде додано).

> Для викладача: перевірити команди `winget` та версію nvm на чистих Windows і macOS під час прогону. Окремі PDF встановлення: Windows, macOS, Linux.

## Крок 3. Обліковий запис GitHub і власний репозиторій

1. Зареєструйтеся або увійдіть на https://github.com.
2. Відкрийте шаблонний репозиторій `<адреса буде додана>` і натисніть **Use this template → Create a new repository**.
3. Назва: `lf-client-<ваше-імʼя>`. Видимість: **Public** (репозиторій має бути публічним на час навчання, щоб ментор міг перевірити PR). Не кладіть у нього паролі, токени чи особисті дані. Натисніть **Create repository**.

**ПЕРЕВІРТЕ:** на сторінці вашого репозиторію є файли `README.md`, `package.json`, папка `app/`.

## Крок 4. Отримання коду на комп'ютер

**КОПІЮЙТЕ** (замініть `<ваш-логін>` і `<ваше-імʼя>`):

```bash
cd ~/Projects          # або будь-яка ваша робоча папка
git clone https://github.com/<ваш-логін>/lf-client-<ваше-імʼя>.git
cd lf-client-<ваше-імʼя>
```

(Windows PowerShell: `cd $HOME\Projects`; папку створіть командою `mkdir $HOME\Projects`.)

**ЯКЩО НЕ ВИЙШЛО (без Git):** на сторінці вашого репозиторію натисніть **Code → Download ZIP**, розпакуйте архів і працюйте з розпакованою папкою (не з .zip). Пізніше ви зможете підключити Git.

## Крок 5. Встановлення Cursor і відкриття проєкту

1. Завантажте Cursor з https://cursor.com і встановіть. Увійдіть в обліковий запис (за потреби корпоративний).
2. Відкрийте папку проєкту: **File → Open Folder** і виберіть `lf-client-<ваше-імʼя>`.
3. На запит «Trust this workspace?» виберіть **Yes, I trust the authors**.

Необов'язково, з терміналу: `cursor .`

**ПЕРЕВІРТЕ:** ліворуч видно дерево файлів; чат агента відкривається за `Ctrl+I` (Windows/Linux) або `Cmd+I` (macOS).

## Крок 6. Запуск застосунку

У вбудованому терміналі Cursor (**Terminal → New Terminal**):

```bash
cp .env.example .env         # Windows PowerShell: Copy-Item .env.example .env
npm install
npm run dev
```

Встановлення може тривати кілька хвилин. Коли термінал покаже, що застосунок готовий, відкрийте http://localhost:3000/en у браузері.

**ПЕРЕВІРТЕ:** відкривається сайт Фонду Лятошинського. Перейдіть на сторінки «Про фонд» і «Контакти»; зверніть увагу, які розділи справжні, а які мають заглушку.

Зупинити застосунок: `Ctrl+C` в терміналі.

**ЯКЩО НЕ ВИЙШЛО:**
- Порт 3000 зайнятий: Next.js запропонує інший, використайте адресу з терміналу.
- `npm install` падає: перевірте `node -v` (потрібно 22+), повторіть із мережею без VPN.
- Сторінка порожня після змін: зупиніть сервер (`Ctrl+C`) і запустіть знову.

База даних тут у пам'яті й наповнюється демо-даними при кожному запуску, тож остаточно нічого зламати неможливо.

## Крок 7. Знайомство з проєктом через агента

Відкрийте новий чат агента (`Ctrl+I` / `Cmd+I`).

**У ЧАТ CURSOR:**

```text
Прочитай README.md і структуру верхнього рівня папок.
Поясни, що робить цей проєкт, для кого він і як організований.
Відповідь не довша за 200 слів.
```

**ПЕРЕВІРТЕ (ваша робота аналітика):** що відповідь вгадала, що пропустила, що вигадала. Порівняйте з тим, що ви бачили в браузері.

## Крок 8. Основи Markdown (5 хвилин)

Достатньо чотирьох конструкцій:

```markdown
# Заголовок
## Підзаголовок
- пункт списку
| Колонка A | Колонка B |
|---|---|
| значення | значення |
```

Усе інше в інструкціях для AI це звичайний текст. Чіткість важливіша за обсяг.

## Крок 9. Постійні інструкції для агента: `AGENTS.md`

`AGENTS.md` лежить у корені проєкту, Cursor читає його автоматично. Аналітик не пише код, але пише інструкції.

**У ЧАТ CURSOR:**

```text
На основі того, що ти знаєш про цей проєкт, напиши стартовий файл AGENTS.md
для нового члена команди, який є бізнес-аналітиком.

Включи:
- однопараграфовий опис проєкту
- основні сторінки та їх бізнес-призначення (таблицею)
- конвенції: TypeScript, без default export, українська (uk) як основна мова
- примітку, що це навчальний репозиторій і БД скидається при кожному запуску
```

Перегляньте результат, **виправте неточності** (це ваша аналітична частина) і збережіть як `AGENTS.md` у корені.

**ПЕРЕВІРТЕ:** закрийте чат, відкрийте новий і запитайте:

```text
Що це за проєкт? Відповідай так, ніби я щойно долучився до команди.
```

Агент має відповісти термінами з вашого `AGENTS.md`. Якщо ні, перезапустіть Cursor.

**Необов'язково:** правила, прив'язані до типів файлів, лежать у `.cursor/rules/`. Створіть одне правило, яке стосується, наприклад, документів у `docs/`.

## Крок 10. Діаграма архітектури (Mermaid)

**У ЧАТ CURSOR:**

```text
Вивчи структуру проєкту, зокрема app/[lang]/, app/api/, app/services/,
app/infrastructure/ та app/di/.

Згенеруй Mermaid-діаграму flowchart TD, що показує:
- основні сторінки
- API-маршрути, які вони викликають
- сервіси, які використовують ці маршрути
- інфраструктуру (моделі/репозиторії БД), від якої залежать сервіси

Підписуй вузли справжніми назвами папок або файлів.
```

Збережіть результат у `docs/architecture.md` (блок коду з міткою `mermaid`). Переглянути діаграму можна в попередньому перегляді Markdown у Cursor або на https://mermaid.live.

**Обговорення:** що на діаграмі відсутнє? Де в цій схемі працюють ваші знання про бізнес?

## Крок 11. Здача: Pull Request

1. Створіть гілку й закомітьте:

```bash
git checkout -b day-1
git add AGENTS.md docs/architecture.md
git status
git commit -m "docs: add AGENTS.md and architecture diagram (day 1)"
git push -u origin day-1
```

2. На GitHub відкрийте запропонований **Compare & pull request** → **Create pull request** (у вашому репозиторії, з гілки `day-1` у `main`).
3. Надішліть ментору **посилання на PR** (канал: `<буде вказано в Moodle>`).

**ПЕРЕВІРТЕ перед комітом:** `git status` не показує `.env`, `node_modules` чи інші службові файли.

**Обов'язкове:** `AGENTS.md` + діаграма. **Додатково:** одне правило в `.cursor/rules`.

## Критерії перевірки (ментору)

1. Виконано всі кроки: `AGENTS.md` і діаграма в PR.
2. `AGENTS.md` відповідає реальному проєкту (немає вигаданих сторінок).
3. Видно власну правку (не лише AI-текст).
4. Немає службових файлів і секретів.
