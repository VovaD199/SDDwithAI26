# Структура курсу в Moodle

> ЧЕРНЕТКА v1.1. Описує, **що і куди** розмістити. Платформа: Moodle 5.2.3, додаткові плагіни не потрібні, відстеження виконання й чекліст не використовуються. Правила зарахування вже є на платформі (сторінка «Rules») і в курсі додатково не згадуються. Усі матеріали українською; англійська версія пізніше.

## Принципи

- Один розділ на кожен день + вступний і довідковий розділи.
- Усе для проходження дня в одному місці: інструкція, презентація, завдання.
- Пропустивший заняття може пройти день самостійно за інструкцією.
- Матеріали ментора (рубрика) **не** публікуються учасникам.
- Файли публікуйте у PDF (з Markdown у репозиторії); джерело правди лишається в Git.

## Загальна структура

| Розділ | Для кого | Вміст |
|---|---|---|
| 0. Старт | Учасники | Про курс, розклад, канал підтримки (правила зарахування вже на платформі, сторінка «Rules») |
| 0.1 Підготовка | Учасники | Інструкція встановлення (Windows / macOS / Linux), чекліст готовності, завдання «надішліть скріншот `git --version` і `node -v`» |
| День 1 | Учасники | Див. нижче |
| День 2 | Учасники | Див. нижче |
| День 3 | Учасники | Див. нижче |
| День 4 | Учасники | Див. нижче |
| Довідник | Учасники | Шаблони дня 4, набір для Cursor, словник термінів, запасні шляхи |
| Для менторів | Менторам (прихований) | Посібник ментора, рубрика, типові проблеми |

## Шаблон розділу «День N»

| № | Елемент Moodle | Вміст | Джерело в репозиторії |
|---|---|---|---|
| 1 | Підпис (Label) | Мета дня, 3–4 речення, очікуваний результат | «Мета дня» з інструкції |
| 2 | Файл | Покрокова інструкція (PDF) | `materials/day-N/day-N-instruction.md` |
| 3 | Файл | Презентація (PDF/PPTX) | *(ще не підготовлено)* |
| 4 | Завдання (Assignment) | Здача: посилання на PR (див. нижче) | «Здача» з інструкції |
| 5 | Форум (необов'язково) | Питання по дню | |

## Вміст по днях

### День 1. Старт і контекст проєкту
- Інструкція: `materials/day-1/day-1-instruction.md`
- Додатково: окремі PDF встановлення (Windows / macOS / Linux), `materials/setup/installation-guide.md`
- Здача: PR з `AGENTS.md` і `docs/architecture.md`

### День 2. Від вимоги до коду
- Інструкція: `materials/day-2/day-2-instruction.md`
- Додатково: безпека токена GitHub (окремий блок «Прочитайте перед MCP»), запасний шлях без MCP
- Здача: PR з `docs/contact-form-feature.md` + посилання на issue

### День 3. Гіпотези та прототипи
- Інструкція: `materials/day-3/day-3-instruction.md`
- Додатково: акаунт Figma з Figma Make (попросити створити заздалегідь)
- Здача: PR з підсумком PoC (без змін коду); опційно аналіз макета
- Додатково (необов'язково): файл `Figma-Make-example.docx` (`materials/moodle/files/`): приклад результату Figma Make й що в ньому перевірити. Посилання на пошарений дизайн Figma вставляє ментор; особистих посилань із токенами в матеріалах немає.

### День 4. Структуровані специфікації
- Інструкція: `materials/day-4/day-4-instruction.md`
- Додатково: `materials/day-4/figma-mcp-setup.md`, шаблони з `materials/day-4/templates/`
- Здача: PR зі специфікацією (8 артефактів з ID); частина 7 (зріз) самостійна, частина 8 (handoff) опційна

## Налаштування елемента «Завдання» (здача)

- **Тип здачі:** текст онлайн (одне поле для посилання на PR) і, за потреби, коментар учасника.
- **Підказка в описі:** «Вставте посилання на Pull Request у вашому репозиторії (гілка `day-N` у `main`). Репозиторій має бути **публічним** на час навчання, а PR відкритим».
- **Доступ ментора:** окремий доступ не потрібен, бо репозиторії публічні.
- **Зворотний зв'язок:** коментар ментора за рубрикою (див. посібник ментора); рубрику учасникам не публікуємо.

## Що потрібно підготувати до публікації

- [ ] Експорт інструкцій у PDF (єдиний стиль, зміст, номери сторінок)
- [ ] Презентації по днях (поки відсутні)
- [ ] Скріншоти у інструкціях (встановлення, Cursor, Figma)
- [ ] Окремі PDF встановлення за ОС
- [ ] Канал підтримки й канал здачі: вказати в плейсхолдерах `<буде вказано в Moodle>`
- [ ] **Курс-пісочниця** (див. нижче): створити й пройти до запуску
- [ ] Перевірка посилань і плейсхолдерів `<…>` у всіх інструкціях
- [ ] Перевірка доступів (Moodle, GitHub, Figma) для зовнішніх учасників
- [ ] Допоміжний Excel: перелік учасників (за домовленістю з мітингу), лише для кураторів

## Курс-пісочниця (обов'язково перед запуском)

Окремий тестовий курс у Moodle 5.2.3 із копією структури. Мета: до запуску перевірити, що учасник реально може пройти курс.

- [ ] Скопіювати структуру розділів і завантажити PDF інструкцій та шаблони.
- [ ] Налаштувати елемент «Завдання» для здачі посилання на PR і перевірити, що ментор бачить здачі та може залишити коментар.
- [ ] Пройти день за днем як учасник (із чистою машиною): інструкції, команди, шаблонний репозиторій, здача PR.
- [ ] Перевірити посилання, плейсхолдери `<…>`, шляхи файлів, відображення PDF.
- [ ] Залучити 1–2 тестових учасників (бажано нетехнічних) і зібрати зауваження до інструкцій.
- [ ] Внести правки в інструкції та шаблонний репозиторій, після чого створити робочий курс.

## Прийняті рішення (07.11.2026)

- Moodle 5.2.3, додаткових плагінів немає; відстеження виконання й чекліст не використовуються.
- Правила зарахування: сторінка «Rules» на платформі, додаткових згадок у курсі не робимо.
- Репозиторії учасників мають бути публічними на час навчання.
- Відеозаписи студенти отримують окремо в Діскорді, у структурі Moodle їх не згадуємо.
- Курс-пісочниця потрібна.
