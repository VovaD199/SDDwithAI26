# Структура курсу в Moodle

> ЧЕРНЕТКА v1. Описує, **що і куди** розмістити. Не знаю версії Moodle, встановлених плагінів і того, як уже налаштовано платформу (правила зарахування, за словами автора, вже на платформі). Тому назви елементів Moodle (Розділ, Файл, Сторінка, Посилання, Завдання, Форум, Відстеження виконання) загальні, а конкретні налаштування треба звірити з вашою платформою. Усі матеріали українською; англійська версія пізніше.

## Принципи

- Один розділ на кожен день + вступний і довідковий розділи.
- Усе для проходження дня в одному місці: інструкція, презентація, запис, завдання.
- Пропустивший заняття може пройти день самостійно: інструкція + запис.
- Матеріали ментора (рубрика) **не** публікуються учасникам.
- Файли публікуйте у PDF (з Markdown у репозиторії); джерело правди лишається в Git.

## Загальна структура

| Розділ | Для кого | Вміст |
|---|---|---|
| 0. Старт | Учасники | Про курс, розклад, правила зарахування (як на платформі), канал підтримки |
| 0.1 Підготовка | Учасники | Інструкція встановлення (Windows / macOS / Linux), чекліст готовності, завдання «надішліть скріншот `git --version` і `node -v`» |
| День 1 | Учасники | Див. нижче |
| День 2 | Учасники | Див. нижче |
| День 3 | Учасники | Див. нижче |
| День 4 | Учасники | Див. нижче |
| Довідник | Учасники | Шаблони дня 4, набір для Cursor, словник термінів, запасні шляхи |
| Для менторів | Менторам (прихований) | Посібник ментора, рубрика, типові проблеми |

## Шаблон розділу «День N»

| № | Елемент Moodle | Вміст | Джерело в репозиторії |
|---|---|---|---|
| 1 | Підпис (Label) | Мета дня, 3–4 речення, очікуваний результат | «Мета дня» з інструкції |
| 2 | Файл | Покрокова інструкція (PDF) | `materials/day-N/day-N-instruction.md` |
| 3 | Файл | Презентація (PDF/PPTX) | *(ще не підготовлено)* |
| 4 | Посилання / Відео | Запис заняття | запис після проведення |
| 5 | Завдання (Assignment) | Здача: посилання на PR (див. нижче) | «Здача» з інструкції |
| 6 | Форум (необов'язково) | Питання по дню | |
| 7 | Відстеження виконання | Умови завершення елементів | |

## Вміст по днях

### День 1. Старт і контекст проєкту
- Інструкція: `materials/day-1/day-1-instruction.md`
- Додатково: окремі PDF встановлення (Windows / macOS / Linux), `materials/setup/installation-guide.md`
- Здача: PR з `AGENTS.md` і `docs/architecture.md`

### День 2. Від вимоги до коду
- Інструкція: `materials/day-2/day-2-instruction.md`
- Додатково: безпека токена GitHub (окремий блок «Прочитайте перед MCP»), запасний шлях без MCP
- Здача: PR з `docs/contact-form-feature.md` + посилання на issue

### День 3. Гіпотези та прототипи
- Інструкція: `materials/day-3/day-3-instruction.md`
- Додатково: акаунт Figma з Figma Make (попросити створити заздалегідь)
- Здача: PR з підсумком PoC (без змін коду); опційно аналіз макета

### День 4. Структуровані специфікації
- Інструкція: `materials/day-4/day-4-instruction.md`
- Додатково: `materials/day-4/figma-mcp-setup.md`, шаблони з `materials/day-4/templates/`
- Здача: PR зі специфікацією (8 артефактів з ID); частина 7 (зріз) самостійна, частина 8 (handoff) опційна

## Налаштування елемента «Завдання» (здача)

> Налаштуйте відповідно до правил зарахування на платформі (терміни, повторна здача, оцінювання).

- **Тип здачі:** текст онлайн (одне поле для посилання на PR) і, за потреби, коментар учасника.
- **Підказка в описі:** «Вставте посилання на Pull Request у вашому репозиторії (гілка `day-N` у `main`). Переконайтеся, що PR відкритий і репозиторій доступний ментору».
- **Доступ ментора:** якщо репозиторій приватний, учасник має додати ментора як співавтора (або зробити репозиторій публічним) і згадати це в завданні. Уточніть політику приватності з організаторами.
- **Зворотний зв'язок:** коментар ментора за рубрикою (див. посібник ментора), без публікації рубрики учасникам, якщо так вирішено.
- **Терміни й статуси:** взяти з правил на платформі.

## Умови завершення (completion)

| Елемент | Умова |
|---|---|
| Інструкція / презентація / запис | Переглянуто (за бажанням) |
| Завдання дня | Здано |
| Розділ «День N» | Завершено, коли здано завдання |
| Курс | Умови зарахування з правил платформи |

## Що потрібно підготувати до публікації

- [ ] Експорт інструкцій у PDF (єдиний стиль, зміст, номери сторінок)
- [ ] Презентації по днях (поки відсутні)
- [ ] Записи занять (після проведення)
- [ ] Скріншоти у інструкціях (встановлення, Cursor, Figma)
- [ ] Окремі PDF встановлення за ОС
- [ ] Канал підтримки й канал здачі: вказати в плейсхолдерах `<буде вказано в Moodle>`
- [ ] Перевірка посилань і плейсхолдерів `<…>` у всіх інструкціях
- [ ] Перевірка доступів (Moodle, GitHub, Figma) для зовнішніх учасників
- [ ] Допоміжний Excel: перелік учасників і прогрес (за домовленістю з мітингу), лише для кураторів

## Що не відомо й потрібно уточнити

- Версія Moodle й доступні плагіни (відстеження виконання, чекліст, відео).
- Чи є вже на платформі розділ із правилами зарахування й як він названий (щоб послатися).
- Приватні чи публічні репозиторії учасників; як ментор отримує доступ.
- Де хоститимуться записи (Moodle, зовнішнє сховище) та їх обмеження за розміром.
- Чи потрібен окремий курс-«пісочниця» для перевірки перед запуском.
