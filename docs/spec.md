# Специфікація

## Проблема

Бізнес-аналітики та PM (зокрема зовнішні учасники) не вміють системно використовувати AI для роботи з вимогами: AI вигадує факти, вимоги лишаються нечіткими, зв'язок «вимога → код → тест» губиться. Наявні матеріали (6 сесій) розрізнені: різні інструменти (Cursor, Claude Code) і різні кейси (lf-client, Order Desk, пауза підписки).

## Користувачі

- **Учасники курсу:** бізнес-аналітики, PM, зокрема нетехнічні та початківці, на Windows, macOS і Linux. Зовнішня аудиторія, не лише співробітники компанії.
- **Викладачі/ментори:** проводять заняття, перевіряють здані PR, ведуть запис і Moodle.

## Вимоги

### Формат і організація
- [ ] Практичний воркшоп: 4 дні по 4 години; ведучі показують частину, учасники виконують інший приклад під керівництвом.
- [ ] Теорія мінімальна: принципи роботи з вимогами та їхня якість.
- [ ] Покрокові інструкції на кожен день (PDF/документи, промпти) у Moodle; записи занять доповнюють інструкції.
- [ ] Той, хто пропустив заняття, може пройти його самостійно за інструкцією та записом.
- [ ] Презентації до занять.

### Технічний старт
- [ ] Основний інструмент: Cursor.
- [ ] Один наскрізний кейс: шаблонний репозиторій lf-client; кожен учасник працює у власній копії локально.
- [ ] Запуск без Docker, мінімум інструментів (Git, Node.js 22); БД у пам'яті з seed-даними.
- [ ] CLI-команди у трьох блоках (Windows / macOS / Linux); складні налаштування в окремих PDF.
- [ ] Показати роботу з Git і GitHub та налаштування AI-інструмента для нетехнічних учасників.
- [ ] Опція: нова гілка для роботи з новим функціоналом.
- [ ] Запасні шляхи: Download ZIP замість `git clone`; за можливості Codespaces; вправи без MCP.

### Зміст
- [ ] День 1: середовище, контекст проєкту, AGENTS.md, Mermaid.
- [ ] День 2: трасування фічі, GitHub MCP (власний MCP-сервер планується), аналіз впливу, AC.
- [ ] День 3: sandbox-PoC, чекліст валідації, Figma Make.
- [ ] День 4: SDD (Spec Kit / OpenSpec / BMAD), структурована специфікація, Figma MCP, PoC/MVP-зріз.
- [ ] Навчальні матеріали описують ризики токена GitHub і MCP: безпека, обмеження організації, проблеми підключення.

### Перевірка
- [ ] Учасники здають посилання на PR у власному репозиторії; правила зарахування визначені й передані учасникам (вже винесено на навчальну платформу).

## Поза межами (non-goals)

- Навчання програмуванню та інженерним практикам.
- Вибір «єдиного правильного» SDD-фреймворка (порівнюємо, не обираємо).
- Продакшн-розробка lf-client; зміни в ньому лише навчальні та одноразові.
- Docker як обов'язкова умова.
